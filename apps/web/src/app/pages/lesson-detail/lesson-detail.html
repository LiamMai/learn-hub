State Management with Context API

Share state across a component tree without prop-drilling — and know when not to.

Core Concepts

Context lets a value flow down a component tree without passing it through every intermediate component's props. A Provider publishes a value; any descendant can read it with useContext, no matter how deeply nested.

Architecture

A typical setup pairs one createContext call with a Provider component that owns the actual state, and a custom hook (like useAuth below) that reads the context and throws a clear error if it's used outside the Provider.

Lifecycle

Every consumer re-renders whenever the Provider's value changes — even if a component only reads one field off a larger object. Memoizing the value (useMemo) avoids creating a new object on every render and re-rendering consumers unnecessarily.

Common Use Cases

Theme, authenticated user, locale, and feature flags are classic fits — values that many distant components need but that change rarely. Frequently-changing, high-frequency state (like a text input's value) usually belongs in local state, not Context.

Best Practices

Keep each Context focused on one concern rather than one giant "app state" context — it keeps re-renders scoped and makes each Provider easy to reason about in isolation.
